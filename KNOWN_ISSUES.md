# Known Issues & Open Questions

## Open Questions

### Syscall tooltip — only first match per text node
The TreeWalker-based syscall wrapping in `CodeBlock.astro` processes only the first syscall name per text node. In practice this works because Shiki splits code into many small `<span>` elements, but a line like `wait(fork())` might miss the inner call. Low priority since it rarely occurs.

### Hardcoded localhost fallback in CodeBlock
`CodeBlock.astro` line ~302 shows `ws://localhost:8090` as a developer hint when the terminal URL isn't configured. This only appears if `PUBLIC_TERMINAL_URL` is empty (production builds always set it). Not a bug but could confuse contributors.

### DiffView uses positional line diff
The diff computation in `DiffView.astro` compares lines by position (line N vs line N). This works for the known mistake/fix pairs but would break for files with inserted/deleted lines. A proper LCS diff algorithm would be more robust if more pairs are added.

### Concept graph is hardcoded SVG
`ConceptGraph.astro` has node positions and edges hardcoded. Adding a new lesson requires manually updating the SVG layout (Lesson 16 was added by hand). Consider generating from `os-lessons.ts` data in the future.

### ForkVisualizer is lesson 02 specific
`ForkVisualizer.astro` shows a generic fork lifecycle diagram, not dynamically derived from the actual C code. Adding visualizations for other lessons would require new components.

### Expected Output panels are a snapshot
`site/src/data/captured-outputs.json` is generated by running every example in the real sandbox:
`cd validate && TERMINAL_URL=ws://localhost:8099 CAPTURE=1 node --experimental-strip-types examples.mjs`
(after `bash validate/local-container.sh`). Re-run it after changing course code. The old
`site/scripts/capture-outputs.py` ran programs on the host with a 5 s cut-off — do not use it
(it produced "[Program timed out after 5 seconds]" panels, and runs fork demos without limits).

### First Run after the containers slept
A sleeping student container starts in a few seconds, but right after a new image is deployed the
first start can take up to ~40 s while Cloudflare pulls the image. The presenter's sandbox is woken
in the background by the header badge, so lectures are not affected; students may see one slow start.

### "Waiting for input" detection reads kernel wait channels
The server marks a program as waiting for keyboard input when its process sleeps in the terminal
read path (`n_tty_read` / `wait_woken` in `/proc/<pid>/wchan`). Programs that wait in `select()` or
`poll()` (the chat clients) are not detected; for those the "Insert sample input" button is shown
for as long as the program runs.

### pthread_cleanup example crashes 1 time in 10
`lesson-12-pthreads/03-pthread_cleanup.c` returns from inside `pthread_cleanup_push/pop` at random —
undefined behaviour that musl punishes with SIGSEGV. Labelled as intentional; see
`docs/course-fixes-for-review.md`.

### Billing alert is a manual step
PRD task T07b: the Wrangler token cannot create notifications. Set the $10 usage alert in the
Cloudflare dashboard (Notifications → Add → Usage Based Billing).

## Resolved

_(Issues fixed during audit are listed here for reference)_

- `.astro/dev.log` files were committed to git — removed from tracking, added `.astro/` to gitignore
- Run button uploaded only the file's basename while compile commands used `folder/file.c` — every
  example in a subfolder failed to compile (lessons 05, 07–11, 14). Files now keep their paths, and
  headers they `#include "..."` are uploaded with them.
- Ten course files did not compile or misbehaved — fixed, listed in `docs/course-fixes-for-review.md`.
- Students could collide on System V keys, ports and `/tmp` names, and a later student could inherit a
  previous one's `/tmp` and `/dev/shm` files (Unix uids are reused). Each session now gets private
  IPC/network/mount namespaces, and cleanup removes those files (security probes S20, S21).
- `/dev/shm` did not exist in Cloudflare's container, so POSIX named semaphores failed in production.
- The connection rate limit was approximate (refused 0 of 360 floods); now an exact per-IP counter (S13).
- Shell-integration events split across two WebSocket messages were missed (no exit chip, stuck
  auto-run); the parser now carries unfinished sequences over (unit check U01).
